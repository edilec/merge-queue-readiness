# Merge Queue Readiness documentation

The policy JSON has exactly `requiredChecks` (1–100 unique names), `minApprovals` (0–100) and `maxAgeMinutes` (1–10080). The snapshot has exactly `headSha` (40 hex digits), `capturedAt` (UTC ISO timestamp), `mergeable` (boolean), `unresolvedThreads` (0–10000), `checks` (0–1000 entries), and `approvals` (0–1000 entries). A check has `name`, `sha`, and `status` (`success`, `failure`, `pending`, `cancelled`). A review has `reviewer`, `sha`, and `state` (`approved`, `changes-requested`, `dismissed`). Check names permit letters, digits, spaces, periods, slashes, hyphens and underscores; reviewer identifiers permit letters, digits, periods, hyphens and underscores. Names are limited to 80 characters.

Required checks must each have exactly one successful result on `headSha`. Zero results, results for another commit, unsuccessful results and duplicate head results block readiness. At least `minApprovals` distinct reviewers must approve the head commit. A current changes-requested review, unresolved thread or conflict blocks readiness. This is a snapshot evaluator: it does not verify the exporter, repository identity, branch protection settings, queue position or changes made after capture.

Inputs are limited to 262144 bytes each. Invalid, unreadable, non-UTF-8 or over-limit input is `incomplete`; capture older than the policy maximum or later than `--at` is `incomplete`. The run is never ready with unknown evidence. JSON is decoded strictly as UTF-8. Unknown schema fields are rejected. The tool reads two named files only and does not recurse through the filesystem. A fixed maximum of 1000 checks/reviews bounds work. The CLI performs no network or write operations.

stdout is one JSON report with `schemaVersion: "1"`, `tool: "merge-queue-readiness"`, `status`, `summary`, and sorted `findings`; stderr has a human summary. Findings sort by code unit on `(location.file, location.pointer, ruleId)`. Input file names are logical `@policy` and `@snapshot` roles; pointer identifies a field in the exact supplied file. Exit 0 means ready, exit 1 means evaluated blockers, exit 2 means incomplete evidence or invalid invocation. Invalid options, paths or time produce empty stdout and a usage message on stderr; unreadable or malformed evidence produces an `incomplete` JSON report. Messages never contain raw input values.

Stable rules and severities: `input-unreadable`, `input-invalid`, `input-too-large`, `capture-stale`, `capture-future`, `missing-evidence` are warnings that force `incomplete`; `check-missing`, `check-wrong-commit`, `check-unsuccessful`, `approval-insufficient`, `approval-wrong-commit`, `changes-requested`, `review-unresolved`, `merge-conflict` are errors. A duplicate head check is `missing-evidence` because the exporter has given contradictory state.
