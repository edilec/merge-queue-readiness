# Merge Queue Readiness documentation

The policy JSON has exactly `requiredChecks` (1–100 unique names), `minApprovals` (0–100) and `maxAgeMinutes` (1–10080). The snapshot has exactly `headSha` (40 hex digits), `capturedAt` (UTC ISO timestamp), `mergeable` (boolean), `unresolvedThreads` (0–10000), `checksComplete` and `reviewsComplete` (booleans), `checks` (0–1000 entries), and `approvals` (0–1000 entries). The exporter must set completeness flags true only after collecting the full check and review sets for the named head. A check has `name`, `sha`, and `status` (`success`, `failure`, `pending`, `cancelled`). A review has `reviewer`, `sha`, and `state` (`approved`, `changes-requested`, `dismissed`). Check names permit letters, digits, spaces, periods, slashes, hyphens and underscores; reviewer identifiers permit letters, digits, periods, hyphens and underscores. Names are limited to 80 characters.

Required checks must each have exactly one successful result on `headSha`. With a complete check export, zero results, results for another commit and unsuccessful results block readiness; duplicate head results are ambiguous and incomplete. At least `minApprovals` distinct reviewers must approve the head commit. With a complete review export, a current changes-requested review, unresolved thread or conflict blocks readiness. The export must provide one effective review per reviewer for the head; multiple states without ordering are incomplete. An incomplete check or review export is incomplete, not an inferred blocker. This is a snapshot evaluator: it does not verify the exporter, repository identity, branch protection settings, queue position or changes made after capture.

Inputs are limited to 262144 bytes each and JSON container depth two (root at depth zero). Invalid, unreadable, non-UTF-8 or over-limit input is `incomplete`; capture older than the policy maximum or later than `--at` is `incomplete`. The run is never ready with unknown evidence. JSON is decoded strictly as UTF-8. Unknown schema fields are rejected. The tool reads two named files only and does not recurse through the filesystem. A fixed maximum of 1000 checks/reviews and a 5000-millisecond execution deadline after root resolution bound work. The library evaluator accepts an injected deadline and clock for deterministic boundary checks. The CLI performs no network or write operations.

stdout is one JSON report with `schemaVersion: "1"`, `tool: "merge-queue-readiness"`, `status`, `summary`, and sorted `findings`; stderr has a human summary. Findings sort by code unit on `(location.file, location.pointer, ruleId)`. Input file names are logical `@policy` and `@snapshot` roles; pointer identifies a field in the exact supplied file. A missing check points to its required policy entry; observed checks point to their snapshot ordinals. Exit 0 means ready, exit 1 means evaluated blockers, exit 2 means incomplete evidence or invalid invocation. Invalid options, paths or time produce empty stdout and a usage message on stderr; unreadable or malformed evidence produces an `incomplete` JSON report. Messages never contain raw input values, including check names.

Stable rules and severities: `input-unreadable`, `input-invalid`, `input-too-large`, `input-depth-limit`, `timeout`, `capture-stale`, `capture-future`, `missing-evidence`, `review-ambiguous` are warnings that force `incomplete`; `check-missing`, `check-wrong-commit`, `check-unsuccessful`, `approval-insufficient`, `approval-wrong-commit`, `changes-requested`, `review-unresolved`, `merge-conflict` are errors. A duplicate head check is `missing-evidence` because the exporter has given contradictory state.
